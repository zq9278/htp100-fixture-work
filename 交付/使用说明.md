# 眼盾检测工装

两端工程均已改为专用耗材工装，必须配套更新。日期：2026-10-21。

## 固件与操作

- `HTP100_Fixture_Main.hex`：G070 主板，从 `0x08000000` 烧录。
- `HTP100_Fixture_Screen_New.hex`：H750 新屏幕应用；`HTP100_Fixture_Screen_Old.hex`：H750 旧屏幕应用。每次构建同时生成两套，分别沿用原工程新旧屏 LCD 初始化序列。双击 `Burn_Screen.bat` 后选择 `1 新屏幕` 或 `2 旧屏幕`。
- 两种屏幕应用均从外部 QSPI `0x90000000` 烧录，保留原来的内部 Flash BOOT。屏幕工程原缺失的 GCC 链接脚本已补齐，地址与现有 BOOT、SystemInit 和原 HEX 一致。
- HEX 自带地址；BIN 需手动选择上述地址。ELF 用于调试。
- 主页提供三个独立入口，点击即等待耗材，操作结束后显示成功或具体失败原因。成功为整页绿色背景、大字提示，蜂鸣器短鸣两声（150ms 响、120ms 停、150ms 响），同一结果持续上报不会重复响。
- WS2812 的 15 颗灯同步结果：只有通过常亮绿色、失败（包括已报废）常亮红色；其余状态一律常亮蓝色，包括启动、待机、等待、写入、加热、稳定计时、取消及返回。拔出复位后恢复蓝色，使用专用常亮逻辑，不调用原产品的故障闪烁效果。
- 目标温度、实时温度、稳定计时、结果说明与失败原因统一使用 36 像素字体（原为 28），成功/失败标题为 48 像素。长提示已分行，保留底部操作按钮空间。
- 完成后保持结果并关闭加热；检测到耗材连续拔出至少 600ms 后，自动清空温度、稳定计时和本件结果，继续等待下一件，仍执行当前所选功能。初始化/演示入口也按相同方式连续处理，不会因耗材一直插着而重复写入。
- 耗材/温度/加热/写入等单件故障同样支持拔出后复位。通讯中断、供电事件、主动取消、初次等待超时或非法指令不自动重启，需返回主页重选。返回按钮会先取消并等待主板确认，避免退出后继续自动处理。

| 功能 | 行为 | 加热 | 耗材 EEPROM 写入 |
| --- | --- | --- | --- |
| 眼盾初始化 | 将 256 字节逐字节恢复为 FF，每字节回读校验 | 无 | 显式恢复出厂空白状态 |
| 制作演示耗材 | 写入原有演示/服务标识 `0x0202` 并回读校验 | 无 | 仅 `0x03–0x04`，不写已使用标记 |
| 眼盾出厂检测 | 先检查使用标记；未报废耗材才沿用原 PID 加热，目标 ±3℃ 连续稳定至少 2 秒即提示“耗材正常”并停热 | 有 | 全程只读，保留原内容 |

出厂检测独立读取 EEPROM `0x01–0x02` 的使用标记：`0xFFFF` 表示未标记，其余值按已标记处理，直接以红色大字显示“耗材已报废”，不启动加热。读取失败也不启动加热，提示“耗材标记读取失败”。演示/服务标识不会覆盖已报废判断；加热过程中也持续复查。此检查不依赖熔断写入开关，既不会写入使用标记，也不会清除已有标记。报废件拔出并确认后，自动等待下一件。

第三项出厂检测的失败页现在显示具体读取位置和数据，并提供“诊断详情”：

- 已报废：显示标记地址 `0x01–0x02`、实际读值（如 `0x0001`）与要求值 `0xFFFF`。
- 通信失败：显示器件（EEPROM 7位地址 `0x50` 或 TMP112 `0x48`）、出错寄存器、无应答/NACK、超时等原因，以及 HAL 状态和完整 I²C 错误码。
- 温度错误：显示 TMP112 `0x00` 寄存器的原始16位数据与最后有效传感器温度；读取失败明确显示无有效读值，不拿旧值或零值冒充本次结果。
- 过温或加热超时：显示实际温度、目标、过温持续时间、检测用时和本件最长稳定时间。PWM故障明确指出 `TIM14_CH1` 加热输出，不将其混同于耗材数据错误。
- 诊断详情保留36像素字体，可上下滑动；显示重试次数、SCL/SDA电平、EEPROM服务字段等。SCL/SDA为失败读取当时采样；无通信记录时明确标注未采样。

失败数据会锁存，后续探测或插拔不会覆盖；拔出确认进入下一件时清空。本次通信扩展到版本2，**主板与屏幕必须配套更新**。

PID 保持原参数：Kp=30、Ki=5、Kd=5，控制周期 150ms。实际控制目标 43.0℃；界面目标显示 42.5℃，实测温度减去 0.5℃后显示。温度离开允许范围会清零稳定计时。受采样周期影响，成功判定发生在满足 2 秒后的首次有效采样。

过温判定使用未扣补偿的传感器温度：连续达到或超过 44℃ 满 5 秒才判为过温，停热并以红色显示失败。任何有效采样低于 44℃ 都清零这段计时；新任务、拔出复位、取消或故障也会清零。过温确认期间不提前判定合格，避免温度还在超限时被 2 秒稳定条件提前放行。正常完成为绿色，失败为红色。配置位于主板 `App/Inc/fixture_config.h`。

首次等待耗材超时 30 秒，批量处理拔出后会持续等待下一件，加热检测超时 120 秒。耗材断开、温度读取失败、PWM 启动失败、过温、取消、断电事件或屏幕心跳中断均停热并给出原因。屏幕每 250ms 发心跳，主板 3 秒未收到有效心跳即停热并停止自动复位；屏幕 4 秒未收到当前事务状态提示通讯超时。

初始化本身会清除原 EEPROM 内容，包括已有演示标识；这是该入口的明确操作。出厂检测不会自动初始化、制作演示耗材、写入已使用标记或增加治疗计数。熔断开关已设为 0，并添加编译保护，启用熔断会直接拒绝编译。

主板 CMake 已停用原治疗控制器、压力 ADC/调参、电机驱动、主机存储及计数和旧串口协议模块；源文件保留。WS2812 驱动用于工装专用结果指示，原产品灯效流程停用。屏幕停用原治疗界面、图片、弹窗、治疗计时中断及旧通讯，保留 LCD、触摸、LVGL 和 UART 基础驱动。供电芯片初始化继续保留。

## 通讯协议

沿用硬件串口：屏幕 USART1 ↔ 主板 USART2，115200、8N1，无流控。双方改用同一份 `fixture_wire.h` 定义；修改时同步两边。

固定 48 字节，小端序；版本2，旧版本1的18字节帧不再兼容：

| 字节 | 含义 |
| --- | --- |
| 0–1 | 帧头 E7 7E |
| 2 | 版本 02 |
| 3 | 开始 01 / 心跳 02 / 取消 03 / 状态 81 |
| 4–5 | 事务号，同事务重复开始只回状态，不重复写入 |
| 6 | 功能：初始化 1 / 演示 2 / 出厂检测 3 |
| 7 | 状态：待机 0 / 等耗材 1 / 写入 2 / 加热 3 / 稳定 4 / 成功 5 / 失败 6 |
| 8 | 原因，见 `fixture_wire.h` 的 FX_* 枚举 |
| 9 | 最近耗材探测结果 |
| 10–11 | 原始传感器温度，int16，单位 0.01℃；-32768 表示无有效数据 |
| 12–13 | 实际控制目标，单位 0.01℃ |
| 14–15 | 连续稳定时间，单位 ms，最大 2000 |
| 16 | 有效位：bit0标记 / bit1服务字段 / bit2温度原始值 / bit3本次I²C操作失败 |
| 17–19 | 最后I²C器件7位地址、寄存器地址、HAL状态 |
| 20–21 | 使用标记（原始高低字节组成的数值） |
| 22–23 | 服务字段 |
| 24–25 | TMP112原始16位寄存器值 |
| 26–27 | 操作尝试次数；bit0=SCL、bit1=SDA（1高0低） |
| 28–31 | 完整HAL I²C错误码 |
| 32–35 | 本件检测用时，ms；失败/成功后锁存 |
| 36–37 | 连续过温时间，ms |
| 38–39 | 本件最长达标稳定时间，ms（上报最大2000） |
| 40 | 最后I²C操作：1读取、2写入 |
| 41–45 | 保留，填零 |
| 46–47 | 前46字节的 CRC16/MODBUS，初值FFFF，多项式A001 |

请求帧中7–45填零。流解析支持拆包、粘包、噪声及CRC错误后的重新同步。主板每200ms上报同帧状态与诊断快照，只接受当前事务和功能匹配的心跳/取消。功能运行中不会切换到另一项功能。

## 编译与验证

已配置的 Windows 环境可运行：

```powershell
powershell -ExecutionPolicy Bypass -File tools/build_fixture.ps1
python -m pip install -r tools/test-requirements.txt
python tools/test_fixture.py
python tools/test_fixture_eeprom.py
python tools/test_fixture_led.py
python tools/render_fixture.py
```

需要 CMake、Ninja、arm-none-eabi 工具链在 PATH。构建脚本使用盘符根目录的 `htp100-fixture-work` 目录联接，绕过本机 ST CMake 在中文工作目录下崩溃的问题；联接指向本工程，不复制源码。两端产物会复制至本目录。

已完成两端 Release 编译、真实 ARM C 状态机仿真、真实 EEPROM 驱动的 HAL 模拟验证，以及实际屏幕 ELF 的 LVGL 渲染检查。界面预览位于 `界面预览/`；渲染时用 LVGL 软件绘制替代 DMA2D，并模拟 LCD/UART 硬件。

状态机测试覆盖三项功能隔离、连续稳定与越界重计时、毫秒计数回绕、耗材断开、温度/PWM/过温故障、等待/加热/通讯超时、取消、供电事件、重复指令和串口流恢复。EEPROM 测试验证探测只读、初始化全 FF、演示仅写 03/04、写入及回读错误，以及不写入已使用标记。

尚未连接实物烧录或测量加热输出；电气连接、真实温升曲线、传感器掉线、屏幕掉电及两端断线停热仍需上机验收。当前 HEX 可用于这一步联调。

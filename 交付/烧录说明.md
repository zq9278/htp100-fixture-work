# 两端固件烧录

接好对应电路板的电源与 J-Link SWD（SWDIO、SWCLK、GND、VTref，建议同时接 NRST），关闭占用探针的调试软件，然后双击对应入口：

| 双击文件 | 烧录对象 | 固件 |
| --- | --- | --- |
| `Burn_Main.bat` | STM32G070CB 主板 | 同目录 `HTP100_Fixture_Main.hex` |
| `Burn_Screen.bat` | STM32H750XB 屏幕 | 选择新屏或旧屏后加载对应固件 |

两个入口共用同目录的 `flash_fixture.ps1`，请一起保留。屏幕烧录会先询问：`1 - 新屏幕`、`2 - 旧屏幕`、`Q - 退出`。分别使用 `HTP100_Fixture_Screen_New.hex` 和 `HTP100_Fixture_Screen_Old.hex`，没有默认选择，输入错误会重新询问。

每次执行 `tools/build_fixture.ps1` 都会编译并交付新旧屏幕两套 HEX/BIN/ELF，分别使用工程里原有的新屏、旧屏 LCD 初始化序列。屏幕 CMake 的默认构建也同时生成两个目标。

脚本自动查找已安装的 JLink.exe，使用 SWD 4000kHz，完成下载、校验、复位和运行。成功显示 `SUCCESS`；失败显示原因并保留窗口，日志位于 `flash_logs/`，屏幕日志名称包含 `New` 或 `Old`。

屏幕入口沿用原 `.jflash` 的 QSPI 引脚：CLK=PF10、nCS=PB6、D0=PF8、D1=PF9、D2=PF7、D3=PF6，只接受 `0x90000000–0x90FFFFFF` 的应用数据。它保留内部 Flash 的原 BOOT；空白屏幕板需要先另外烧录原 BOOT。

主板入口只接受 `0x08000000–0x0801FFFF`。两个入口均在连接探针前检查 HEX 校验和、数据地址和向量表，避免选错固件；不执行整片擦除、解锁或修改选项字节。

主板双击直接烧录，屏幕双击选择屏幕类型后烧录。也可在命令行使用可选参数：

```powershell
# 仅验证文件、工具路径及生成的命令，不连接探针或烧录
.\Burn_Main.bat -DryRun
.\Burn_Screen.bat -DryRun

# 自动化调用时可以直接指定屏幕类型，跳过选择菜单
.\Burn_Screen.bat -ScreenVariant New -DryRun
.\Burn_Screen.bat -ScreenVariant Old -DryRun

# 多个探针时选择序列号；连接不稳定时降低 SWD 速度
.\Burn_Main.bat -ProbeSerial 123456789 -Speed 1000
.\Burn_Screen.bat -ProbeSerial 123456789 -Speed 1000

# 指定工具位置
.\Burn_Screen.bat -JLinkPath "C:\Program Files\SEGGER\JLink_V954\JLink.exe"
```

也支持环境变量 `JLINK_EXE` 指定 JLink.exe。固件先复制到 ASCII 临时目录再交给 J-Link，以兼容工程中文路径；临时目录包含当次固件快照与命令，可用于排查。若 Windows 用户名导致 TEMP 路径含中文，可在命令行先设置 `$env:TEMP='D:\Temp'`，并确保该目录存在。

已通过两个入口的 DryRun 和错误地址拦截检查；未执行实际硬件烧录。

命令依据：[SEGGER J-Link Commander（LoadFile 默认校验）](https://kb.segger.com/J-Link_Commander#LoadFile)、[SEGGER 外部 Flash loader 选择语法](https://kb.segger.com/J-Link_Multiple_Flashloader#Command_line_parameter)。

# 电源波动后的软件恢复

本次实现已通过 Release 编译和 `git diff --check`，下列硬件验证尚未执行。

## 实现

- `main()` 入口启动 IWDG1，先于 HAL、PLL 和 SDRAM 初始化。预分频 256、重装值 999，在标称 32 kHz LSI 下为 8 秒；实际时间随 LSI 频率变化。
- 启动阶段仅在完成一个初始化阶段后喂狗。运行阶段仅在串口、触摸、LVGL 和状态处理均返回后喂狗。中断、错误死循环、DMA2D 等待均不喂狗。
- 触摸 EXTI/I2C 错误回调只提交请求。主循环执行有 20 ms 超时参数的 I2C 事务；失败释放触摸状态，最多每秒尝试一次 I2C4 和 GT911 初始化。每 50 ms 补充轮询，处理遗漏的中断边沿。坐标完整读取并确认成功后才发布。
- 每轮串口处理最多 512 字节，避免持续来流饿死其他任务。
- SDRAM 命令失败进入现有错误处理，由 IWDG 复位，不再继续使用未初始化的 SDRAM。
- 保留此前的缓存同步修复；未恢复同步等待垂直消隐或首帧背光门控。

## 调试变量

- `screen_reset_flags`：本次启动读取的 RCC RSR 原始复位标志，读取后清除硬件标志。`RCC_RSR_IWDG1RSTF` 表示独立看门狗复位。
- `screen_boot_stage`：本次启动的当前进度，1 入口、2 系统时钟完成、3 串口语言等待结束、4 SDRAM 完成、5 触摸初始化返回、6 显示端口完成、7 UI 创建完成、8 完整主循环完成。此变量不跨复位保存。
- `touch_io_error_count`：本次运行触摸 I2C 错误累计次数。

## 上板验收

1. 稳定供电，分别验证中英文、眼盾安装/未安装、点击/滑动/长按/松手、充电插拔；持续运行确认无意外看门狗复位。
2. 在主循环人为注入不喂狗的死循环，保持 CPU 运行，检查约 8 秒后重新启动，并检查 IWDG1 复位标志。单纯用调试器暂停 CPU 不能替代该测试。
3. 让触摸设备临时不响应：界面和串口应继续运行，不产生错误点击；设备恢复后应恢复触摸。记录错误计数和实际恢复时间。
4. 重复原始“英文、未安装眼盾、充电后拔电/不稳定上电”步骤，记录供电稳定到恢复界面的时间、是否出现复位循环以及复位标志。
5. 分别验证硬故障和外设等待卡住后，IWDG 能够复位；检查上电 UI 初始化最慢耗时，确认小于实际看门狗窗口。

## 边界

软件只能在芯片有效工作条件下提供恢复。IWDG 启动前的启动代码故障、外部执行存储器失效，以及电压低于芯片有效范围不保证能由这段软件恢复。本次没有更改 BOR Option Bytes；持续欠压仍需匹配硬件的欠压复位和供电设计。看门狗复位恢复屏幕板，不代表已验证主机治疗状态的恢复行为。

IWDG 时钟与初始化依据：[ST STM32H7 IWDG 驱动](https://github.com/STMicroelectronics/stm32h7xx-hal-driver/blob/master/Src/stm32h7xx_hal_iwdg.c)。
